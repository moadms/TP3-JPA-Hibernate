# TP 3 : Gestion Avancée des Entités Salle, Réservation, Utilisateur et Équipement avec JPA et Hibernate

Ce projet implémente une solution robuste et professionnelle pour la gestion des réservations de salles et de leurs équipements dans un environnement d'entreprise, en utilisant **JPA (Java Persistence API 2.2)** et **Hibernate ORM 5.6**, adossé à une base de données en mémoire **H2**.

---

## 1. Architecture du Modèle de Données & Relations

Le modèle métier est composé de quatre entités interconnectées afin de couvrir les différentes relations JPA :

1. **`Utilisateur` (`t_utilisateurs`)** :
   - Identifiant unique matricule (`matricule`), nom complet (`nomComplet`), courriel professionnel (`emailPro`) et rôle d'accès (`role`).
   - Relation **One-to-Many** bidirectionnelle vers `Reservation` (`@OneToMany(mappedBy = "auteurDemande")`).

2. **`Salle` (`t_salles`)** :
   - Référence interne (`codeSalle`), désignation (`nomSalle`), capacité d'accueil (`capacite`), localisation d'étage (`etage`).
   - Relation **One-to-Many** bidirectionnelle vers `Reservation` (`@OneToMany(mappedBy = "salleConcernee")`).
   - Relation **Many-to-Many** propriétaire vers `Equipement` via table de jointure dédiée `t_salle_equipement_assoc`.

3. **`Equipement` (`t_equipements`)** :
   - Code matériel d'inventaire (`codeMateriel`), désignation (`designation`), état fonctionnel (`etatFonctionnel`).
   - Relation **Many-to-Many** inverse avec `Salle` (`@ManyToMany(mappedBy = "listeEquipements")`).

4. **`Reservation` (`t_reservations`)** :
   - Horaires (`debutReservation`, `finReservation`), motif (`objetReunion`), statut de traitement (`statut`).
   - Relations **Many-to-One** vers `Utilisateur` (`auteurDemande`) et vers `Salle` (`salleConcernee`).

## 2. Configuration JPA (`persistence.xml`)

La configuration cible une base de données H2 en mémoire avec dialecte Hibernate approprié et journalisation SQL détaillée :

```xml
<persistence-unit name="tp3_gestion_salles" transaction-type="RESOURCE_LOCAL">
    <provider>org.hibernate.jpa.HibernatePersistenceProvider</provider>
    
    <class>ma.enset.tp.model.Utilisateur</class>
    <class>ma.enset.tp.model.Salle</class>
    <class>ma.enset.tp.model.Equipement</class>
    <class>ma.enset.tp.model.Reservation</class>

    <properties>
        <property name="javax.persistence.jdbc.driver" value="org.h2.Driver"/>
        <property name="javax.persistence.jdbc.url" value="jdbc:h2:mem:tp3db;DB_CLOSE_DELAY=-1"/>
        <property name="javax.persistence.jdbc.user" value="sa"/>
        <property name="javax.persistence.jdbc.password" value=""/>

        <property name="hibernate.dialect" value="org.hibernate.dialect.H2Dialect"/>
        <property name="hibernate.hbm2ddl.auto" value="create-drop"/>
        <property name="hibernate.show_sql" value="true"/>
        <property name="hibernate.format_sql" value="true"/>
    </properties>
</persistence-unit>
```

## 3. Traces d'Exécution et Tests

Lors de l'exécution de la classe principale `App.java`, le schéma relationnel complet est généré par Hibernate :

```sql
create table t_salles (
    id_salle bigint generated by default as identity,
    capacite_personnes integer,
    code_salle varchar(30) not null,
    localisation_etage varchar(255),
    nom_salle varchar(100) not null,
    primary key (id_salle)
);

create table t_utilisateurs (
    id_utilisateur bigint generated by default as identity,
    courriel_pro varchar(150) not null,
    identifiant_unique varchar(60) not null,
    nom_prenom varchar(120) not null,
    role_utilisateur varchar(35),
    primary key (id_utilisateur)
);

create table t_equipements (
    id_equipement bigint generated by default as identity,
    code_materiel varchar(50) not null,
    designation_materiel varchar(120) not null,
    etat_marche varchar(50),
    primary key (id_equipement)
);

create table t_salle_equipement_assoc (
    fk_salle bigint not null,
    fk_equipement bigint not null,
    primary key (fk_salle, fk_equipement)
);

create table t_reservations (
    id_reservation bigint generated by default as identity,
    debut_creneau timestamp not null,
    fin_creneau timestamp not null,
    objet_session varchar(200),
    etat_demande varchar(30),
    fk_demandeur bigint not null,
    fk_salle_reservee bigint not null,
    primary key (id_reservation)
);
```

### Requête JPQL avec Fetch Join
```java
List<Reservation> reservations = em.createQuery(
```
